# 手机端适配调整方案（规划 v1，2026-08-10）

> 状态：**仅规划，未实施**。评分系统上线前完成本规划，待用户确认后实施。
> 关联：评分/观察库新功能尚未部署，手机适配须与这些新功能的 UI 同步设计，避免建成后返工。

## 一、现状盘点（已具备的响应式能力）

| 机制 | 覆盖范围 | 说明 |
|---|---|---|
| `@media (max-width:900px)` 自动响应 | 网格单列、stats 纵向、搜索/筛选换行、admin-nav 横滚、评分数字网格单列 | 真机窄屏自动生效 |
| `@media (max-width:1280px)` | 卡片内边距收窄、字号缩小、header 字号 | 平板/小窗 |
| `body.mobile-mode` 手动开关 | 头部纵向、网格单列、卡片缩小、弹窗全屏、后台面板收窄、图表区单列 | 管理员可手动切「手机版」，与媒体查询有重叠 |

**已较好适配**：专家列表单列、搜索/筛选换行、卡片基础缩放、详情弹窗全屏（`modal-content max-width:100%`）、联系方式移动端原生 `tel:`/`mailto:`（v5.8.10 已修）。

## 二、真机缺口清单（按角色/页面）

### A. 前端用户 · 浏览与详情
1. **详情弹窗内部布局**：`detail-score-row` 在 mobile-mode 仍为 `row`（两列并排），375px 屏下评分卡偏挤；`detail-score-sub-area` 已单列。分值分布图 `flex:1 1 380px` 在 375px 屏需确认不溢出。
2. **评分细则浮窗（"?"）**：前端专家详情页"?"浅灰图标 hover 浮窗，目前为固定宽度弹层，手机无 hover、需改为点击展开且全屏宽度。
3. **悬浮翻页导航** `page-navigation-float`：窄屏 `min-width:36px` 可用，但位置/遮挡需复核。
4. **点击区域**：卡片内小元素（标签、收藏心形）需 ≥44×44px 命中区。

### B. 前端用户 · 联系方式（已修，复核即可）
- 移动端 `tel:`/`mailto:` 原生调用已做；微信/未知点击复制需有 toast 反馈确认。

### C. 管理员后台（最大缺口）
1. **后台表格横向滚动体验差**：专家管理、合作项目等表格仅靠 `.table-scroll-wrapper` 横向溢出。手机上应转**卡片列表**或**冻结首列 + 横向滚动**。
2. **表单可用性**：新增/编辑专家、系统设置等表单的 input 宽度、label 换行、按钮全宽未统一手机化。
3. **调分弹窗（新功能，待建）**：评分项须改为**大号数字步进器**，操作意见 `textarea` 全宽，保存/淘汰按钮 **sticky 底部**。
4. **观察库列表（新功能，待建）**：卡片式，展示低分项（红字）、掉库原因、观察阶段（剩余天数/逾期/待淘汰）、操作入口；手机需独立样式。
5. **月报 PDF（canvas 绘制）**：手机上预览/下载入口与缩放。

### D. 登录/认证
- 登录卡片窄屏样式、magic link 邮件跳转回 App、本地密码登录输入框/按钮全宽。

### E. 全局
1. **断点不统一**：现有 900/1280/1366/1600/1920/2560 与 `mobile-mode` 双轨；建议补 `@media (max-width:480px)` 小手机档，并让 `mobile-mode` 与媒体查询规则收敛（减少重复）。
2. **横向溢出治理**：扫描 `white-space:nowrap`/固定宽度（header-update、admin-nav、各类 table）确保无意外横向滚动条。
3. **触控目标**：正文 ≥14px，可点元素 ≥44×44px。
4. **弹窗统一规范**：所有 modal 手机上近全屏、顶部关闭、底部操作 sticky。

## 三、调整方案（分阶段，含与新建功能协同）

### 阶段 0 · 规范与基建（先于功能）
- 统一断点：保留 `@media (max-width:900px)` 为主响应档，新增 `@media (max-width:480px)`；`mobile-mode` 仅作为「手动强制」开关，规则与媒体查询共用同一套 class（避免两份样式漂移）。
- 建立移动端 token：触控目标尺寸、基础字号、弹窗内边距变量。
- 横向溢出扫描并修复。

### 阶段 1 · 前端浏览/详情（独立于评分）
- 详情弹窗内 `detail-score-row` 在 ≤480px 改为纵向堆叠；分值图 `minWidth` 改为 `0` 自适应。
- 评分细则浮窗改为点击展开、手机全宽。
- 卡片命中区加大。

### 阶段 2 · 与「五星星评分 + 观察库」新功能**同步建设**（关键，避免返工）
> 评分/观察库上线时一并交付手机样式，不要等上线后再补。

- **专家详情评分区**：维度/综合星改为移动友好横向条或大字；评分项证据（提取依据）可折叠展开。
- **观察库列表（手机卡片）**：
  - 卡头：姓名 + 领域 + 综合（红字 <3★）
  - 低分项：直接列出 <3★ 项（如 ②资质 2★、④荣誉 2★）
  - 掉库原因标签：综合评分低于 3★
  - 观察阶段：剩余天数 / 已逾期 / 待淘汰
  - 操作：调分 / 淘汰 / 看记录（按钮全宽或两列）
- **调分弹窗（手机）**：评分项大号步进器（− 数字 +）、操作意见 textarea 全宽、底部 sticky「保存（必填意见）/ 淘汰」。
- **操作记录（手机）**：主管理员看完整列表（含他人）；子管理员只看「我」的操作（按 `operatorId` 过滤）——见下方权限说明。

### 阶段 3 · 后台表格与表单
- 关键表格手机转卡片列表（专家管理、合作项目、操作记录）。
- 表单 input/label/按钮全宽化，长表单分区可滚动。

### 阶段 4 · 登录与月报
- 登录卡片窄屏、magic link 回跳提示。
- 月报手机预览/下载。

## 四、观察库操作记录可见性规则（本次确认）

- **主管理员**：可查看观察库操作记录的**完整版**（含所有管理员、系统自动操作）。
- **子管理员**：仅可查看**自己的操作记录**（按 `operatorId` 过滤，不含他人、不含系统批量）。
- 实现：操作记录查询接口/渲染处加 `if (currentUser.role !== 'master') filter by operatorId === currentUser.id`；UI 上对子管理员隐藏「全部/筛选他人」入口。
- 此规则与手机适配无关，但观察库手机列表/记录页须一并落实该过滤。

## 五、验收标准（实施后）

1. iPhone SE（375px）/ 主流安卓（390px）下：无横向滚动条、无元素溢出、可点区域 ≥44px。
2. 专家列表→详情→联系→（管理员）观察库→调分 全链路手机可用。
3. 观察库操作记录主/子管理员可见范围符合第四节规则。
4. 评分/观察库新功能上线即带手机样式（阶段 2 同步交付）。
